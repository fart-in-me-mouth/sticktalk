# Security review — 2026-11-13

Reviewed `bb2edc7`: server/SFU, desktop/client-core/PWA security boundaries, and Oracle + private Pi deployment. Static review, not a penetration test. No product changes, builds, listeners, or visible windows. Severity reflects this friends-only application's exposure through public HTTPS; no Critical finding identified.

## Findings

| ID | Severity | File:line | Concrete scenario | Recommended fix |
|---|---|---|---|---|
| S1 | High | `crates/server/src/launch.rs:248-275` | **ACL replacement bypasses permission containment on removal.** A member with View Channel + Manage Roles, but an overwrite denying Read History, submits `SetOverwrites { overwrites: [] }`. Checks inspect only submitted entries, so deleting the deny restores history access the actor did not possess. Other users' denies can also be silently removed. | Authorize the old-to-new ACL delta, including removed entries/bits, against pre-mutation permissions. Preserve entries the actor cannot change; test empty and partial replacements. |
| S2 | High | `crates/server/src/google.rs:417-422,442-492` | **A stolen session can become permanent account ownership.** Link accepts the attacker's Google token without proving the victim's existing login method. For Google-only victims, the same session can first set a password without fresh Google proof, then unlink the victim's Google identity. Logging out the stolen session does not remove these new credentials. | Require recent proof of an existing login method for link/unlink and first-password creation; bind one-use reauthentication to the operation and session. |
| S3 | High | `crates/server/src/http.rs:70-102`; `crates/server/src/state.rs:461` | **Slow downloads can exhaust all 128 HTTP permits.** The timeout ends at response headers; the permit survives for the entire response stream with no body/write deadline. One user can accumulate stalled large-file downloads until login, REST, and new WS upgrades all return unavailable. Public installer/static downloads provide an unauthenticated variant when large assets are deployed. | Bound response lifetime/slow-client writes, including at Caddy; separate download admission from auth/control capacity and impose per-user/IP concurrency limits. |
| S4 | Medium | `crates/server/src/resumable.rs:112-143,161-235`; contrast `crates/server/src/files.rs:225-267` | **Resumable uploads bypass multipart abuse accounting.** They never charge the 250 MiB/day ledger or apply multipart's default 1 GiB/user cap. With zero/unlimited limits (the configuration defaults), one declared large upload can reserve nearly all admissible local spool space for 24 hours without sending its bytes; others cannot upload. Oracle's 25 MiB/file setting mitigates the single-reservation case, not the daily-accounting bypass. | Share daily/quota reservation accounting across both protocols; cap unfinished reservations per user and expire idle reservations sooner. Ship explicit finite public-server defaults. |
| S5 | Medium | `crates/sfu/src/transport.rs:58-68`; `crates/server/src/voice.rs:193-203,216-222`; `crates/sfu/src/engine.rs:566-575` | **Signaling congestion shuts down chat too.** State signals fan out to every room peer plus an ACK. Bursts while the host's shared DB gate is busy can fill its 128-entry SFU output queue; `try_send` failure terminates the SFU, and the host calls `App::shutdown()`. This is a code-confirmed failure path; saturation was not load-tested. | Revoke/drop the offending voice session on overload, preserve mandatory cleanup through a reserved/control path, and isolate voice failure from the chat service. |
| S6 | Medium | `crates/server/src/google.rs:429-440` | **Normal password changes leave stolen sessions valid.** Only the password hash changes; existing tokens, sockets, and voice sessions remain authorized until their original expiry (up to 30 days). The separate administrator reset route does revoke sessions. | Atomically revoke other sessions on password change, rotate the current token, and disconnect affected WS/voice sessions using the shared revocation path. |
| S7 | Medium | `crates/server/src/backup.rs:63-82`; `crates/server/src/blob.rs:101-137`; `deploy/pi/README.md:37-40` | **Pi data and backups are plaintext at rest.** SQLite snapshots and attachments are written unchanged to an ordinary ext4 volume; Tailscale and HMAC protect transport/authenticity, not a stolen HDD or filesystem reader. The supplied deployment does not establish disk encryption. | Encrypt the Pi volume and backups, with recovery keys held separately by the owner. Document who can decrypt and retained-backup deletion semantics. |
| S8 | Low | `crates/server/src/google.rs:29-36,224-236,335-343`; `crates/client-core/src/oauth.rs:26-35`; `crates/server/src/browser.rs:451-464` | **No ID-token nonce/replay binding.** Native sign-in accepts a valid Google ID token repeatedly until expiry; neither authorization flow requests a nonce and the verifier has no nonce claim. Someone who has captured such a token can mint fresh StickTalk sessions after logout. This requires token theft; it is not a signature or PKCE bypass. | Issue a short-lived server challenge, request/verify its nonce, and consume it once for sign-in/link. Retain the existing state/PKCE checks. |
| S9 | Low | `crates/server/src/resumable.rs:351-364` | **`GET /api/v1/guilds/{id}/storage` returns global storage statistics.** Any user can create their own guild, pass its owner check, and observe other guilds'/DMs' aggregate committed and in-progress upload sizes plus host free space. | Scope aggregates to the requested guild and hide host-wide metrics behind the local administrator CLI. |
| S10 | Low | `Cargo.lock:3590,5046,5808,5852,7842` | **Dependency audit is not clean:** five vulnerability advisories plus five informational warnings. Current reachability is qualified below; no remotely exploitable account/chat attack was established from these alerts alone. | Upgrade affected dependencies where active; document narrowly scoped exceptions for inactive/dev-only paths and enforce audit in CI. |

## Verified OK by inspection

- **Passwords/sessions:** Argon2id v19, 19,456 KiB / 2 passes / 1 lane, random 16-byte salts; two hashing slots and dummy-hash login failures. Sessions/tickets/reset codes use 32-byte OS randomness and SHA-256 storage. Sessions expire after 30 days, at most five/user. Logout/device revocation and reset redeem paths invalidate sessions; login rechecks the verified account/hash after hashing. Login/register have IP and username buckets; reset has an IP bucket and a high-entropy, expiring, single-use administrator-issued code.
- **Google:** pinned RS256 keys, audience/issuer/expiry/issued-at/email verification, identity lookup by `sub` rather than email, bounded/coalesced JWKS refresh with redirects/proxies disabled. Signup tickets expire in ten minutes and are consumed transactionally. Nonce gap is S8.
- **Authorization:** traced REST snapshots, history/extent, files (including before 304), uploads, roles/overwrites, and WS messages/replies/edits/deletes/pins/reactions/invites/moderation/voice. Guild channel access uses the scoped evaluator; DMs/groups require membership and ownership where appropriate. Role edit/assignment/reorder and kick/ban/voice moderation have hierarchy gates. Private attachment downloads require current Read History. ACL changes invalidate replay and removed visibility closes queued streams. Exceptions found: S1 and S9.
- **Public route inventory:** health, meta, browser capabilities, push public key, update latest/artifact, and login/signup/OAuth bootstrap intentionally lack user/channel ACLs. Reset redemption requires its secret code; update publish requires a separate release token plus signed manifest. No additional unguarded private REST route was identified. Message search is client-local; no server message-search endpoint exists.
- **Input/media/storage:** JSON 16 KiB; WS 512 KiB with nested MessagePack/depth checks; multipart/chunk bytes bounded while streaming. Random storage keys, sanitized filenames, forced attachment download, sniffed raster types and `nosniff`; image dimensions/pixels/allocation and encoder concurrency bounded. No interpolated SQL found in production server code. Live PWA renders message text as escaped nodes and permits only HTTP(S) links. GIF API destination is fixed and CDN hosts explicitly allowlisted; redirects disabled.
- **Private node:** HMAC covers method/path/time/nonce/offset/size/digest/Range; persistent one-use nonces and a 60-second timestamp window; opaque single-component keys. CLI binds only loopback or literal Tailscale-range IP, never wildcard/LAN/public. Tailscale policy remains an operator prerequisite.
- **Remote control:** SFU binds grants to exact voice sessions/controller, sequences, active screen, and 1,000 events/s; revoke/disconnect/stream withdrawal release control. Local consent and held-key/button release logic exist. **Native injection is deliberately disabled** (`crates/client/src/voice/native.rs:527-531`); received input revokes control. Thus real SendInput/surface confinement/hotkey release is not implemented or OS-validated, not claimed safe-and-working.
- **Updater/web/deploy:** embedded ed25519 key verifies the manifest before trusting fields; installer SHA-256/size rechecked before apply, newer-version and same-origin HTTPS policy enforced (loopback HTTP test exception). Browser cookies are Secure, HttpOnly session, host-only, SameSite Strict; mutations require exact Origin + session-bound CSRF and WS cookie auth requires matching Origin. CSP includes `frame-ancestors 'none'`; root service worker caches only shell allowlisted assets, never `/api/`; API replies are `no-store`. VAPID private key remains server-side with Unix mode 0600. Oracle Caddy supplies TLS/HSTS with loopback upstream; service has restrictive account/filesystem/capabilities/UMask and root-only env file setup. No default administrator password or public admin CLI exists.
- **Privacy limits:** no message text, bearer tokens, SDP, or keystroke logging found in production server/SFU callsites; grant/revoke metadata is logged as intended. IPs feed transient rate buckets, not account records/access logs. Pi journal is size-bounded with seven-day retention; Oracle journal retention is host-dependent. Message deletion tombstones live content and denies attachment access, but serialized command receipts can retain prior results for ten minutes; backups retain historical data and Pi deleted blobs remain for 15 days. **Account deletion is absent** (disable is not erase); define and implement an owner-approved erasure/backup-retention policy.
